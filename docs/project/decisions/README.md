ADR фиксирует не задачу и не коммит, а значимое решение, которое влияет на долгосрочную архитектуру, пользовательский контракт или безопасность.

## Статусы

- **Предложено** — рассматривается, но не является текущим контрактом.
- **Принято** — подтверждено текущим кодом и продуктовым контрактом.
- **Отклонено** — подход рассмотрен или испробован и не используется.
- **Заменено** — решение ранее использовалось, но заменено другим ADR.

Записи не удаляются при смене решения. Новый ADR ссылается на заменённый, а старый получает статус `Заменено`.

## Когда нужен ADR

ADR нужен при изменении:

- ролей и границы продукта;
- network/security boundary;
- protocol или persisted data format;
- ownership и lifecycle системных ресурсов;
- runtime/WSL/Docker основы;
- принципа установки, обновления или распространения;
- значимого подхода, который уже дал отрицательный результат и может быть ошибочно повторён.

Обычный bugfix, test или локальный refactoring не требует отдельного ADR.
